# Internationalization

Each page below declares a `lang` field in its YAML front matter. The reader picks it up on navigation, switches to a matching voice automatically, and remembers your manual voice choice per language.

```markdown
---
lang: fr
---

# Votre contenu...
```

| Page | Front matter | Expected voice |
| ---- | ------------ | -------------- |
| [Français](i18n/french.md) | `lang: fr` | French |
| [Italiano](i18n/italian.md) | `lang: it` | Italian |
| [Suomi](i18n/finnish.md) | `lang: fi` | Finnish |
| [Español](i18n/spanish.md) | `lang: es` | Spanish |
| [中文](i18n/chinese.md) | `lang: zh` | Chinese |
| [日本語](i18n/japanese.md) | `lang: ja` | Japanese |

## What to verify

1. Open a language page: the voice picker should jump to a voice of that language without any manual action.
2. Pick a different voice of that language in the panel, navigate away and back — your choice is remembered for that language only.
3. Chinese/Japanese pages: sentences must break at 。 ！ ？ even though there is no space after them; word highlighting still follows the spoken word.
4. Return to an English page: the English (or default) voice comes back.

## Voice availability notes

- macOS/iOS ship French, Italian, Spanish, Japanese and Chinese voices out of the box. **Finnish may need to be downloaded** (System Settings → Accessibility → Spoken Content → System Voice) or use Chrome's built-in Google voices.
- If no voice matches the page language, the reader falls back to the system default voice rather than failing.
- Priority order for the effective language: front matter `lang` → `$docsify.screenreader.lang` → `<html lang>` → browser locale.
